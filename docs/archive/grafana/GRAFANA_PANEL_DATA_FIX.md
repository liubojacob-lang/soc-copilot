## 🎯 根本原因分析

### 问题所在：时间窗口使用错误

**错误的查询**:
```logql
topk(10, sum by (agent_id) (count_over_time({job="soc-copilot"}[1h])))
                                                         ^^^^
                                                         问题：只有1小时
```

### 执行流程分析

```
1. count_over_time(...[1h])
   └─> 计算每1小时滑动窗口内的日志数
   └─> 返回时间序列: [10:00=5, 11:00=3, 12:00=2, ...]

2. sum by (agent_id)
   └─> 按 agent_id 分组
   └─> 每个agent一个时间序列

3. Grafana 使用 instant: true
   └─> 取时间序列的最后一个值
   └─> 如果最近1小时只有2条日志，就显示2！
```

### 数据验证

**Agent agent-001 的实际数据**:
```
时间点数量: 24 个小时
24小时总计: 61 条告警
最后1小时:   2 条告警  ← 错误显示了这个！

最近5个时间点:
  1772078400: 1
  1772082000: 5
  1772085600: 1
  1772089200: 2
  1772092800: 2  ← Grafana 显示这个
```

**攻击类型 ssh_bruteforce 的实际数据**:
```
时间点数量: 26 个小时
24小时总计: 173 条告警
最后1小时:   3 条告警  ← 错误显示了这个！
```

---

## 🔧 修复方案

### 核心修改

将所有统计类面板的时间窗口从 `[1h]` 改为 `[24h]`：

```logql
# ❌ 错误（只统计最后1小时）
topk(10, sum by (agent_id) (count_over_time({job="soc-copilot"}[1h])))

# ✅ 正确（统计整个24小时）
topk(10, sum by (agent_id) (count_over_time({job="soc-copilot"}[24h])))
```

### 修改的面板

| 面板 ID | 面板名称 | 修改内容 |
|---------|---------|----------|
| 1 | 告警总数 | `[1h]` → `[24h]` |
| 2 | 严重告警 | `[1h]` → `[24h]` |
| 3 | 高危告警 | `[1h]` → `[24h]` |
| 5 | 攻击类型分布 | `[1h]` → `[24h]` |
| 6 | 严重级别分布 | `[1h]` → `[24h]` |
| 7 | Top 10 攻击源 IP | `[1h]` → `[24h]` |
| 8 | 攻击类型排名 | `[1h]` → `[24h]` |
| 9 | Agent 告警分布 | `[1h]` → `[24h]` |

**注意**: 面板 4（告警趋势）保持 `[5m]` 不变，因为它需要显示时间趋势。

## 📊 LogQL 查询说明

### count_over_time() 参数说明

```logql
count_over_time({job="soc-copilot"}[时间窗口])
                                        ^^^^^^^
                                        关键参数

[1h]  - 统计1个滑动小时窗口内的日志数
[5m]  - 统计5个滑动分钟窗口内的日志数
[24h] - 统计24个滑动小时窗口内的日志数
```

### 查询返回值

```logql
# 使用 [1h] 时间窗口
sum by (agent_id) (count_over_time({job="soc-copilot"}[1h]))
└─> 返回时间序列: [[10:00, 5], [11:00, 3], [12:00, 2], ...]
└─> Grafana 取最后一个值: 2  ❌

# 使用 [24h] 时间窗口
sum by (agent_id) (count_over_time({job="soc-copilot"}[24h]))
└─> 返回时间序列: [[2025-02-25 08:00, 58], [2025-02-26 08:00, 61]]
└─> Grafana 取最后一个值: 61  ✅
```

### 面板类型与查询

| 面板类型 | 时间窗口 | 说明 |
|---------|---------|------|
| **stat** (数字卡片) | `[24h]` | 显示总数 |
| **piechart** (饼图) | `[24h]` | 显示分布 |
| **bargauge** (条形图) | `[24h]` | 显示排名 |
| **table** (表格) | `[24h]` | 显示列表 |
| **timeseries** (时间序列图) | `[5m]` | 显示趋势 |
| **logs** (日志) | 无窗口 | 显示原始日志 |

## 📝 经验总结

### 教训

1. **时间窗口选择很重要**
   - 统计类面板应使用与 Dashboard 时间范围匹配的窗口
   - 趋势类面板应使用较小窗口（如 5m）

2. **Grafana instant 查询的特性**
   - `instant: true` 会取时间序列的最后一个值
   - 不是所有查询都适合使用 instant 查询

3. **验证数据的方法**
   - 使用 Loki API 直接验证查询结果
   - 对比时间序列的总和 vs 最后一个值

### 最佳实践

```logql
# ✅ 统计面板 - 使用与 Dashboard 相同的时间范围
sum(count_over_time({job="soc-copilot"}[24h]))

# ✅ 趋势面板 - 使用较小的时间窗口
sum(count_over_time({job="soc-copilot"}[5m]))

# ✅ 排名面板 - 结合 group by 和合适的时间窗口
topk(10, sum by (field) (count_over_time({job="soc-copilot"}[24h])))
```
