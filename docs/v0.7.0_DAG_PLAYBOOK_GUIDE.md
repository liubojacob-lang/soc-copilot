## What's New in v0.7.0

### DAG Playbook Engine

**Core Features:**

- **DAG Playbook Definitions** - Define complex workflows with nodes and edges
- **Concurrent Execution** - Multiple nodes can run simultaneously
- **Conditional Branching** Route execution based on node outputs
- **Retry & Backoff** - Configurable retry policies per node
- **Run Cancel & Resume** - Cancel running runs and resume from failure point
- **Node Attempts Tracking** - Detailed logs for each retry attempt
- **Enhanced UI** - DAG visualization and node status monitoring

### Database Changes

**New Tables:**

- `playbook_definitions` - Store DAG playbook definitions
- `playbook_node_runs` - Track individual node executions
- `playbook_node_attempts` - Track retry attempts
- `playbook_approvals` - Human approval workflows (v0.7.2)

**Updated Tables:**

- `playbook_runs` - Added `engine_version`, `failure_strategy`, `cancel_requested_at` fields

## API Examples

### Playbook Definitions

#### Create a DAG Playbook Definition

```bash
curl -X POST http://localhost:8000/api/playbook-definitions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "name": "Parallel Threat Analysis",
    "version": "1.0.0",
    "description": "Concurrent TI lookup and asset enrichment",
    "dag": {
      "nodes": [
        {
          "id": "extract",
          "name": "Extract IOCs",
          "type": "extract_iocs",
          "inputs": { "text": "$.context.alert_text" }
        },
        {
          "id": "ti_lookup1",
          "name": "OTX Lookup 1",
          "type": "ti_lookup_otx",
          "inputs": { "ioc": "$.extract.ips.0" }
        },
        {
          "id": "ti_lookup2",
          "name": "OTX Lookup 2",
          "type": "ti_lookup_otx",
          "inputs": { "ioc": "$.extract.ips.1" }
        },
        {
          "id": "score",
          "name": "Risk Score",
          "type": "risk_score",
          "inputs": {}
        }
      ],
      "edges": [
        { "source": "extract", "target": "ti_lookup1" },
        { "source": "extract", "target": "ti_lookup2" },
        { "source": "ti_lookup1", "target": "score" },
        { "source": "ti_lookup2", "target": "score" }
      ]
    }
  }'
```

#### List All Playbook Definitions

```bash
curl http://localhost:8000/api/playbook-definitions \
  -H "Authorization: Bearer YOUR_TOKEN"
```

#### Get Specific Definition

```bash

  -H "Authorization: Bearer YOUR_TOKEN"
```

### DAG Playbook Execution

#### Run a DAG Playbook (Dry Run)

```bash
curl -X POST http://localhost:8000/api/playbook-definitions/{definition_id}/run \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "mode": "dry_run",
    "input_context": {
      "alert_text": "Suspicious activity from 192.168.1.100"
    },
    "failure_strategy": "fail_fast"
  }'
```

#### Run a DAG Playbook (Apply Mode - Admin Only)

```bash
curl -X POST http://localhost:8000/api/playbook-definitions/{definition_id}/run \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer ADMIN_TOKEN" \
  -d '{
    "mode": "apply",
    "input_context": {
      "alert_text": "Suspicious activity from 192.168.1.100"
    }
  }'
```

### Run Status & Monitoring

#### Get Run Status

```bash
curl http://localhost:8000/api/playbook-definitions/runs/{run_id} \
  -H "Authorization: Bearer YOUR_TOKEN"
```

#### Get All Node Runs for a Run

```bash
curl http://localhost:8000/api/playbook-definitions/runs/{run_id}/nodes \
  -H "Authorization: Bearer YOUR_TOKEN"
```

#### Cancel a Running Playbook

```bash
curl -X POST http://localhost:8000/api/playbook-definitions/runs/{run_id}/cancel \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
    "reason": "User requested cancellation"
  }'
```

## Node Types

### Available Node Types

| Type             | Description                    | Inputs                             |
| ---------------- | ------------------------------ | ---------------------------------- |
| `extract_iocs`   | Extract IOCs from text         | `text`                             |
| `ti_lookup_otx`  | OTX threat intelligence lookup | `ioc`                              |
| `parse_json`     | Parse JSON data                | `json`                             |
| `decision`       | Conditional branching          | Condition based on inputs          |
| `switch`         | Multi-way branching            | Field value matching               |
| `sleep`          | Delay execution                | `seconds`                          |
| `http_request`   | HTTP request                   | `url`, `method`, `headers`, `body` |
| `webhook_call`   | Send webhook                   | `url`                              |
| `slack_notify`   | Slack notification             | `channel`, `message`               |
| `asset_enrich`   | Enrich asset data              | Asset identifier                   |
| `risk_score`     | Calculate risk score           | TI data, asset data                |
| `action_plan`    | Generate remediation plan      | Investigation results              |
| `timeline_build` | Build timeline                 | Event data                         |

## DAG JSON Format

### Example DAG with Conditional Branching

```json
{
  "nodes": [
    {
      "id": "start",
      "name": "Start",
      "type": "extract_iocs",
      "inputs": { "text": "$.context.alert_text" }
    },
    {
      "id": "check_malicious",
      "name": "Check if Malicious",
      "type": "decision",
      "config": {
        "condition": "$.extracted.total_count > 0"
      }
    },
    {
      "id": "ti_lookup",
      "name": "Threat Intel Lookup",
      "type": "ti_lookup_otx",
      "inputs": { "ioc": "$.extracted.ips.0" }
    },
    {
      "id": "cleanup",
      "name": "Cleanup (Safe)",
      "type": "action_plan",
      "inputs": {}
    },
    {
      "id": "investigate",
      "name": "Investigate (Malicious)",
      "type": "action_plan",
      "inputs": {}
    }
  ],
  "edges": [
    { "source": "start", "target": "check_malicious" },
    {
      "source": "check_malicious",
      "target": "ti_lookup",
      "condition": "$.check_malicious.result == true"
    },
    {
      "source": "check_malicious",
      "target": "cleanup",
      "condition": "$.check_malicious.result == false"
    },
    { "source": "ti_lookup", "target": "investigate" }
  ]
}
```

## Troubleshooting

### Common Errors

**"Cyclic dependency detected"**

- Your DAG contains a cycle
- Check edge connections and remove circular dependencies

**"Unknown node type"**

- Check node `type` field matches available types
- See Available Node Types section above

**"Condition evaluation failed"**

- Check condition syntax: `$.output.field > value`
- Ensure referenced fields exist in node output

### Database Issues

```bash
# Reset database (WARNING: destroys all data)
cd backend
rm ../data/app.db
python main.py  # Will recreate database
```
